Below is a walkthrough of how to use Javascript and Node

What is Node

A dane, Lars Bak, developed the v8 Javascript engine, which ran at imence speeds. Google would use that engine to build the browser. At that time, javascript was primarily utilized in the browser. Some developers wanted to run javascript outside the browser, which is where node.js was conceptualized. Node can run Api's, desktop apps, cli's, scripts and much more, in the javascript language.

How to use Node

To use Node, you must first download it. This can be acomplised at their own site: https://nodejs.org/en/download. On the site there is also a turtorial for downloading downloading the npm, which stands for node package manager. This is essential as it provides access to packages (containing code that serve a goal) developed by others. An example of a popular package is express, which is a server framework. We will use express later to help create an api. This guide is based on Node version 24.

When you have installed Node, you should have access to node in a terminal. When using windows open powershell or git bash, then type node -v.

This will dislpay the version you of Node you are using, and ensures the program is installed. From here create or choose a folder for a project. In this folder create a file, with the extension .js. (like app.js). In this file you can now write a script with javascript.

To run the script use a terminal and type node "filename" .

Servers with Node

One of the benefits of Node, is that you can use Javascript for a webpage's dynamic frontend, and the server backend serving the web pages to the client

Express

One way to quickly create a Node backend server, is to use a library like Express. Express provides the infrastrucure to accept request and route the clients on the website.

To use Express in a file use javascripts import keyword. Type import, then a name of your choice, then the keyword from, and the name of the package you wish to use

As seen in the file-system above, there are acually two files generated package.json and package-lock.json

package.json contains meta-data about the project, and will in our case look like the following file:

package-lock.json contains data about the exact version each dependency may have. This is meant to ensure that everyone with this file, will have the exact same dependencies and avoid "Works on my maschine" issues.

package.json is a file like any other, and can be manually written. You could delete the file in your project, and write it from scratch yourself. The important part i that the name is exactly the same and that the code is written using JSON notaion, and contain recognized keys (like "dependencies").

As stated earlier package.json should contain metadata, and a project often contains more metadata than dependencies. It is possbile to manually write this data, but there is also a way to save yourself some time.

A better start to a Node project

The Node package manager can help you start your project with the command init, that generates a package.json file, with relevant meta-data from your terminal.

This command will generate the package.json file. But we are still missing the package-lock.json file. The same wil be true if you manually write the package.json file. To generate the missing file type into your terminal npm install.

The command will install all dependencies from the "dependencies" key inside package.json. Generating the file with npm init will not add the dependencies field, so be sure to add it manually, in our case just express

Routing

Express already has infrastrucure for routing. simply call the method get() on the server (that we have named app).

Calling get() without any parameters will cause an error, as the method expects a path and a request handler. The request handler is a function, which is possible because in Javascript, functions are first class citizens.

lets start by making a frontpage, when users first see the website. As the error message says, when we type localhost:8080, we access the path /, so we should provide the get method with the path, / as a string. Then we must also pass a function that can handle the clients request and pass a response back to the client. Becuase we will only use this function in this senario, an anonymous function will suffice.

In the code above we provide get() with our path, /, and a handler method, that accepts req, request, and res, response. Then we use the response to send data back to the client. In this case we send JSON back, meaning the website should just display: {"data":"Hello"}.

the response object, is an object that express passes as an argument to any handler method we provide in the get() methods argument. This response object can also send back files, such as a html file.

First frontpage

To make a frontpage create a new file named index.html.

To make a html file type: <!DOCTYPE html> then make a open and closing html tag (<html> and </html>). inside those tags make a head and body tag.

But we are still just sending te same JSON object. To send the file we have to change what the response object is sending to the client. To achieve this we have to call a different method on the response object named sendFile(). The method expects the path of our frontpage file. Its important we provide the full path, or else express will throw an error.

We could manually type the full path, but this would make the code unreliable. If the server is ever hosted anywhere else, wheter under development or in production, the code wil stop working.

Instead lets get the full path programatically. Because we are using commonjs we have access to a variable named __dirname that has the string path of where the script was executed. Because app.js in the root of the project, __dirname is the path to the root of the project. The index file is also in the root of the project, so the path is the same. From here we could concatinate the file name to the end of __dirname, but the better solution is simply to pass __dirname and the filename as seperate arguments to sendFile().
